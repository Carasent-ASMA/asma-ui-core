## API and structural decisions

All existing props, arbitrary children, and runtime exports remain. `variant` is additive:
`label`/`icon` keep action semantics; `checkmark` defaults to `menuitemradio`;
`checkbox` defaults to `menuitemcheckbox`. Selection is controlled by `selected` and
activation by the existing `onClick`. `role` and ARIA attributes allow consumer semantics.
Checkbox visuals reuse `StyledCheckbox decorative`; no nested input/button is introduced.
`icon` is a decorative 20px slot; pass icons with inherited color (for example
`ErrorOutlineIcon color="currentColor"`). `active` plus `id` supports an owner's
`aria-activedescendant`; normal keyboard focus still paints the focus bar.

`dragHandle` supplies only a decorative icon/layout slot. `unavailable` supplies inert
body-colored styling, disabled semantics, and the existing prohibition glyph. Consumers
own the tooltip/description/localization and the reason, ordering, and accessible DnD.

`StyledMenuList` identifies only marked shared rows in the rendered DOM. Fragments and
component/tooltip wrappers are transparent; custom content, explicit dividers and nested
lists break runs. The final row of each run has no separator. A MutationObserver updates
runs after child insertion/removal/reordering. Nested menus own their keyboard navigation;
custom input keys are not intercepted. ToolbarActionGroup no longer inserts hr nodes.

`scroll` defaults to `auto` (more than six shared rows), `true` forces the scroll variant,
and `false` permits a consumer-managed layout. `surface` adds the shared surface to an
unanchored list, including Tab entry to its first enabled row. Anchored menus retain
StyledPopover's Escape/Tab/close/focus-return behavior.
